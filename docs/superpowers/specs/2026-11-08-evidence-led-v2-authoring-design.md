# 证据驱动的 v2 制作与分层验证设计

状态：待确认。本文细化现有设备模拟器设计，不改变 AI 仅在制作阶段参与的边界。

## 意图与范围

制作者应能看见 AI 如何把获准设备的观察整理成固定的 v2 行为模型，并清楚区分模拟器工程正确性与真实设备一致性。当前测试阶段没有真实 AucSeek 包或基线时，允许演示包通过工程验证、由已认证制作者试运行，但不得声称真实设备一致或开放普通使用者。

目标是直接产生可审查的 v2 提案、保留每条规则的证据与推断标记、支持接口/状态和页面可见效果两层差分，并让报告与版本显示验证级别。非目标是自动验证所有硬件效果、执行模型生成代码、绕过真实设备写请求审批、增加练习或评分逻辑、开放匿名或考生运行。

## 考虑的方案

1. 仅提前现有 AI 按钮：改动小，但提案仍进入 v1 Mock 再导入 v2，且自生成断言无法证明设备一致性。
2. 直接生成 v2 提案并用真实设备基线差分验证（选定）：AI 负责建模和指出缺口；工程验证与设备一致性独立报告。需要更明确的采集步骤、基线存储和审阅界面。
3. 常驻对话助手：探索灵活，但建议与证据、修订、验证门槛难以稳定绑定，不作为此轮主流程。

## 制作流程

1. 选择项目和不可变设备包，描述要模拟的能力。连接获授权设备后，由制作者录制一个或多个有序操作场景，包括操作意图、浏览器动作、所选请求/响应观察、刷新及可见页面检查点。真实设备写操作仍逐次审批。敏感字段按现有白名单与脱敏规则处理；截断、缺失或脱敏值不得作为确定性状态更新依据。
2. 制作者确认场景中的关键读写与预期可见效果。系统冻结基线快照，绑定项目、包 ID/哈希、采集草稿 ID、会话与观察 ID。基线只记录获准字段和受限的可见断言；动态字段由制作者选择忽略、类型/范围比较或稳定映射，不能由 AI 擅自忽略。
3. “行为制作”直接请求 v2 提案。后端从持久化证据和基线构造最小、脱敏的模型输入；Worker 返回 v2 行为、建议验证用例及缺口清单。后端校验 schema、规则冲突、路径、证据归属和输入快照，拒绝伪造的 `CAPTURED` 引用。提案只返回给页面，不创建修订；无模型配置时可手工制作。
4. 页面显示每条新增/修改规则的匹配条件、响应、状态操作、观察 ID、`CAPTURED`/推断来源和与当前修订的差异。制作者逐项采纳、修改或拒绝；关联的状态字段及验证用例一起审阅，避免采纳半条规则。缺口作为补采集事项，不充当已验证行为。取消和项目/包/采集版本切换不保存提案。确认后沿用现有不可变 v2 修订接口，服务端再次检查输入版本。新制作流程不经过 v1 导入。

## 分层验证与门槛

- **工程验证**沿用固定解释器和隔离浏览器，检查包启动、规则、制作者确认的断言、刷新/新运行状态、未知接口与外部请求阻断。AI 建议的断言必须经制作者确认；AI 输出不能自行提升验证等级。
- **设备一致性**仅在有真实基线时执行：在隔离模拟器重放同一场景，逐步比对获准请求顺序、关键响应字段与状态读回，以及页面可见检查点。比较规则和基线快照固定在报告中。重放无法稳定复现的浏览器动作、动态值和硬件侧效果须列为未覆盖，不可默认为通过。真实设备基线由先前获授权采集产生；差分验证不在后台悄悄重放真实写操作。
- 报告保留现有 `PASSED`/`BLOCKED` 工程结果，并增加独立的设备一致性结论 `NOT_TESTED`/`PASSED`/`BLOCKED`/`PARTIAL`、证据快照哈希、差异及未覆盖项。没有基线时是 `NOT_TESTED`，不是设备验证通过。
- 工程验证通过、无真实基线时，新版本可标记为 `DEMO_ENABLED`，只允许已认证制作者通过试运行入口启动，页面与版本列表持续显示“仅演示，未验证真实设备一致性”。真实一致性通过后才能为新候选版本评估更高级别；这不自动开放考生入口。本轮不迁移或重分类已有 `ENABLED` 记录，也不将其视为真实设备一致性通过。
- 报告绑定包、行为修订、基线/比较规则及运行时哈希。任一变化需新报告；启用仍要求明确确认未阻断风险。停用、租约、独立 origin、无 AI 的运行时与现有权限约束保持不变。

## 失败与验收

模型不可用、输出不合法、证据跨项目/会话、采集快照变化或并发保存时，提案失败且不修改原修订。基线缺少关键读写时工程报告阻断相应关键能力；缺少真实基线只允许演示级别。页面差分无法比较时报告 `PARTIAL` 和原因，不伪造一致性。接口通过但页面检查点失败，或页面通过但关键接口不符，都不能标为设备一致性通过。

演示包验收覆盖：直接 v2 提案与逐项审阅、取消无副作用、证据与来源可追溯、工程通过后演示试运行、刷新保持/新运行重置、无真实基线时明确 `NOT_TESTED`。有获授权真实设备时另测正反向配置读写、可见页面检查点、动态字段比较与差异定位。未取得真实 AucSeek 包和采集材料前，不作其兼容性声明。

## 实施边界

复用 Java 的不可变草稿、证据、报告与版本实体，Worker 的受限浏览器和固定解释器，Vue 五视图。新增基线快照和差分报告字段/服务；调整 AI 提案端点及行为制作审阅界面。具体表结构、端点命名和 UI 布局由实施计划确定。测试环境先实现新流程；不做旧版本迁移、重分类或历史数据修复，不清理工作区未提交文件和本机数据。
